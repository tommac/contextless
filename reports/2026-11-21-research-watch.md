# ContextlessAI research watch, November 21, 2026

The local morning report was absent at the 12:23 p.m. Eastern check. This watch searched independently, including overlap with the November 20 review. These items were newly identified in that overlap. Dates below are the authors' submission or vendor release dates.

| Decision | New evidence and limitation | Smallest follow-up |
| --- | --- | --- |
| How to compress a retrieval index | MemFolder v1 (Nov 19 preprint) halved the number of Mem0 records. Across three text benchmarks, mean accuracy went from 61.1% to 60.5%. LongMemEval knowledge-update accuracy went from 79.5% to 76.9%. The 99.0% headline is relative retention on this particular store. [Paper and tables](https://arxiv.org/html/2611.26427v1) · [Author code](https://github.com/xuyang-liu16/MemFolder) | Give one reader the same folded index with and without an opportunity to reopen original passages. Count correction errors, exact citations, index-building tokens and reading cost. |
| Whether to reopen completed work | Semantic Context Handoff v1 (Nov 18 preprint) reports mean pass@1 of 86.89% with completed-work evidence available versus 80.00% using only active work, over three runs on 150 SWE-bench tasks. BM25 reached 83.33% using fewer tokens. [Paper, Table 1](https://arxiv.org/html/2611.24357v1) | At a correction, compare reopening the last relevant completed decision with a budget-matched text search. Count fixes and unnecessary reopenings. |
| What to expose in Obsidian | MemoSync v1 (Nov 18 preprint) reports that 132 participants in a four-session coding study scored 59.8% of the available points with memory review, scope controls and usage feedback, 51.1% with static controls, and 47.7% with automatic memory. The features were bundled and the tasks measured coding. [Paper](https://arxiv.org/html/2611.24165v1) | Hold the notes fixed and show half the users which notes reached the previous reader. Time their corrections before a second design round. |
| How to verify actual reader input | Codex CLI 0.171.0 (Nov 20 vendor release) records the prepared prompt and outgoing request using compressed trace shards. Reducing a raw trace requires the recording executable. Letta Code 0.34.68 (Nov 21) supports deltas or truncation markers for external-agent request/response payloads above 2 MiB, with server support for deltas. These are capture semantics. They cannot prove which words influenced a response. [Codex release](https://github.com/openai/codex/releases/tag/rust-v0.171.0) · [Trace implementation](https://github.com/openai/codex/pull/61222) · [Letta release](https://github.com/letta-ai/letta-code/releases/tag/v0.34.68) | Repeat a public prefix with one early correction. Check which exact bytes can be reconstructed and preserve the recorder version and capture status. |
