# ContextlessAI research review · November 20, 2026

The most promising public demonstration is a reader finding a decision that changed, opening the exact passages, and giving the correct answer under a visible budget. The Go engine already has the parts for that demonstration. The open question is how much work the reader should do to find the evidence and when it pays to compress the material it reads.

This review checked the implementation at `04e171c`, the idea vault, the frozen answer-test protocol, and primary research and product sources available through November 20. It is a targeted update to the existing research reports. The findings below were chosen for their ability to change a project decision. Conference results, preprints, single-user experiments, and vendor announcements carry different weight.

## What the project has established

On 150 held-out whole-conversation questions, plain search put 27.6% of the required passages into an 8,000-token budget. Using checked notes as extra search keys raised that to 33.7%. Printing note lines and filling the remainder by search reached 24.3%. At 4,000 tokens the notes arm also had a possible cost on single-source questions, reaching 76.7% versus 85.0% for search. These are passage-presence scores. The 150 questions come from two conversations, eight alternatives were tested without a multiple-testing adjustment, and answer pilots used development questions. [Project results and limitations](../docs/CONTEXT-COMPILER.md#2d-reaching-passages-spread-over-a-conversation)

The November 25 experiment already has a more specific protocol than the roadmap. It fixes 30 questions, with a full-history comparison on 15. Its primary comparison is the code-built turn overview plus paragraph requests against larger-budget search. It also checks contradictions, no-context and oracle controls, and the observed gap to the full-history mean. Use those rules as written. A pass on 15 shared questions would justify reporting the observed gap and interval. A general claim of equivalence needs an adequately powered public replication.

## Experiments that could change the design

| Research | What the authors found | Smallest useful test here |
|---|---|---|
| [LiveCtx, Information Retrieval Journal, Nov 5](https://link.springer.com/article/10.1007/s10791-026-10807-5) | On 500 LongMemEval-S questions under a 131,072-character budget, one-time compression of overflowing retrieved sessions beat the same retrieval without generative compression by 4.4 and 5.0 accuracy points under two graders. The advantage shrank at a looser budget. One reader and a character cap limit transfer. | Give three arms identical candidate passages. Send budgeted verbatim excerpts, a one-shot summary, or checked note keys with one opportunity to open original text. Report results separately for candidate sets that fit and those that overflow. |
| [CompAct-Bench, arXiv preprint, Nov 19](https://arxiv.org/abs/2611.25673) | The authors interrupted successful trajectories, compressed the prefix and continued with the same executor. Aggressive compaction degraded downstream completion across long-horizon tasks. One component uses an internal benchmark. This is a different paper from the October Compact-Bench already in the vault. | Replay a public coding task at a fixed checkpoint. Give the same executor either the original prefix, a summary or a summary with addressable recall. Run the task's own tests and count both recoveries and newly broken cases. |
| [APDMem, EMNLP Industry Track](https://aclanthology.org/2026.emnlp-industry.81/) | Its reader can move from themes and facts to raw messages. The authors report accessing only 8% of the conversations on LongMemEval. That fraction measures access, and cannot establish billed savings for another system. | Count requests, raw bytes opened, index-generation tokens, read and write cache usage, and answer quality for each overview arm. The project's code-built overview is a particularly informative low-cost control. |
| [UTILMEM, EMNLP](https://aclanthology.org/2026.emnlp-main.1639/) | Across 1,717 cases, systems could retrieve the evidence and still fail to combine it, especially with plausible distractors. | For every failed answer, distinguish missing evidence, evidence available but unopened, and evidence read but used incorrectly. Score current value and stale-value contradictions separately. |
| [ProgMem, Findings of AACL](https://aclanthology.org/2026.findings-aacl.120/) | Compiling updates into structured state helped temporal questions on LoCoMo-10 across three Qwen reader sizes. The effect belongs to those readers and tasks. | For one changing value, project an ordered list of assertions, corrections and cancellations from existing fact edges. Compare against chronological retrieval on “what was true then?”, “what is true now?” and insufficient-evidence questions. |
| [MemDev-Bench, arXiv preprint, Oct 20](https://arxiv.org/abs/2610.27524) | Histories constructed from earlier repository tasks helped code localization and editing, but even related history caused regressions when agents reused obsolete experience. | On the repository lane, pair each task with helpful, stale and absent history. Compare test pass rates under the same base commit. Count tasks solved without memory that fail with it. |
| [Towards a Science of Scaling Agent Systems, Google Research](https://research.google/blog/towards-a-science-of-scaling-agent-systems-when-and-why-agent-systems-work/) | Across 180 configurations the value of coordination depended on whether a task was parallelizable. Sequential tasks could deteriorate. | Keep the project's single-agent comparison. Match total budget and separate independent subtasks from dependency chains before attributing a gain to the assembler. |
| [Bursts That Outlast Themselves, arXiv preprint, Nov 10](https://arxiv.org/abs/2611.13412) | A burst of concurrent work left a controlled prefix-cached server with poor reuse well after arrivals subsided. Hosted providers can behave differently. | For the packet layout experiment, log observed cache reads, writes, latency and concurrent calls. Replay cold and warm histories separately. A shared text prefix alone does not measure a cache hit. |

For the public compression comparison, fix the reader, corpus release, candidate generator, answer rubric and paired questions first. Count the overview, recall requests, retries and answer tokens in the end-to-end budget. Report ingest cost separately and amortized at several query counts. Include exact identifiers, corrections, negations, paraphrases and questions that should be declined. A correct quote can still be attached to a misleading title. Blind-score whether the quoted span supports the claim as well as whether the bytes occur.

## Two data-structure opportunities

**Start with the write path.** The record index deletes an old FTS5 entry by textual ID on every upsert, although that FTS column is unindexed. The atom index already addresses rows numerically. A scratch test used all 511 idea-vault Markdown files with Python SQLite 3.51.0 and the record FTS schema. Each timing replaced 100 seeded, distinct rows in one in-memory transaction. In six alternating-order trials the median was **26.46 ms** for the existing predicate versus **8.81 ms** for a unique ID lookup plus rowid delete and reinsert. At 2,044 rows, four copies under distinct IDs, the medians were **47.95 and 12.57 ms**. Both arms preserved the row count, unique IDs, and the same top 20 IDs and BM25 scores for one fixed query with a deterministic tie-breaker. The comparison isolates FTS replacement and excludes file I/O, Git, Go driver overhead and durable commits. [Record and atom index implementation](../internal/store/store.go) · [SQLite FTS5](https://www.sqlite.org/fts5.html)

Prototype an explicit persistent integer search key with unique logical ID. Benchmark import, reindex and chat append using the bundled Go driver on a scratch workspace. Include first inserts, re-upserts, empty text, restart, existing databases and interrupted rebuilds. A cache rebuild may replace search rows, but the same SQLite database also contains run history and provider state. Scope any migration to the affected index tables.

**Make evidence addresses durable before exporting them.** The note checker records byte ranges, but it also splits a turn again for every matched quote. Cache the split for the duration of one check, keyed by immutable turn, then locate the two endpoints in the sorted boundaries. For exported notes include workspace, turn ID, body digest, byte start/end and segmentation version. Keep a readable paragraph ID alongside them. On reimport verify the digest and exact span, including cases where the same phrase occurs twice or the paragraph splitter changes. Measure CPU and allocation savings on multi-quote turns before adding a persistent cache. [Note validation](../internal/engine/notes.go) · [Atom version and byte offsets](../internal/vault/atoms.go)

## Make the Obsidian vault answer engineering questions

The vault already contains 197 ideas, 200 results, 71 sources and 43 field notes. Its existing properties can answer “what should we try?”, “what did we measure ourselves?” and “what have we rejected?” directly. The accompanying Base provides those views and a source index. It reads the existing Markdown properties. A useful next export is one idea per human-readable note, with a stable evidence link for each claim and an explicit link to the experiment that could disprove it. Regenerate machine-owned evidence sections separately from human annotations. [Research review Base](../idea-vault/Research%20review.base) · [Obsidian Bases](https://obsidian.md/help/bases)

Use backlinks first for human inspection. In a November 8 single-user experiment, one-hop wikilink expansion helped 6 queries, harmed 12 and had little effect on 20. No query class showed a significant benefit after correction. The study used model judgments and only 38 queries. A local experiment could compare flat search, one-hop expansion through any link, and expansion only along evidence-bearing relations such as `tested-by`. Measure gains and losses on fresh questions written without seeing the links. [Author's study and protocol](https://huggingface.co/blog/TonyDzi/wikilink-graph-expansion-personal-notes)

## Product changes worth acting on

- Obsidian's November 2 public desktop release supports appending under a specific heading by CLI or URI and reordering Bases filters. That makes an optional “add observation under Evidence” workflow possible while retaining portable Markdown. [Obsidian 1.15](https://obsidian.md/changelog/2026-11-02-desktop-v1.15.0/)
- Google announced file slicing in Gemini's API on November 18. A future document experiment can compare a selected page range with whole-file input, including extraction and billing. Confirm exposure through the project's actual CLI before adding it to a provider profile. [Gemini API changelog](https://ai.google.dev/gemini-api/docs/changelog)
- Anthropic's November 9 release notes document enforced prefix checks on two model versions when reusing thinking blocks after changing earlier context. For any future adapter that replays those blocks, test packet reconstruction and failover with the exact supported model first. [Claude Platform release notes](https://platform.claude.com/docs/en/release-notes/overview)
- Mem0's OSS v3 migration changes search filtering and defaults the relevance threshold to 0.1. Publish the version, threshold and entity filter alongside any head-to-head test. [Mem0 migration guide](https://github.com/mem0ai/mem0/blob/main/docs/migration/oss-v2-to-v3.mdx)

## Public GitHub release

At the time of this review the repository was private and had no license. The strongest launch asset would be a five-minute, model-free replay of one public question: original turns, the packet, evidence opened, exact spans and one recorded failure. Follow it with a pinned LongMemEval-S result using the same reader and judge for plain BM25, full history where it fits, ContextlessAI, Mem0 and a second system such as Graphiti. Publish per-question outcomes, uncertainty, versions, cost and the script that regenerates the table. Cite dataset terms and fetch public data by version. The benchmark authors have revised the histories, so recording the hash matters. [LongMemEval implementation and data revisions](https://github.com/xiaowu0162/LongMemEval)

The launch claim should describe the measured budget, questions and observed quality. If the cheap overview wins, lead with it. If search ties, publish the simpler baseline and the failures that explain the tie. Before opening a repository, choose a license compatible with the copied provider code, inspect the full history and untracked vault/research material for private content, and check terms for the exact CLI integrations included in the demo. No claim about the safety of the repository history follows from this review.
