# What an agent can recover with a fixed reading budget

November 20, 2026

A useful design for ContextlessAI is to keep the original archive and let the agent carry unfinished questions across reads. For example, a question about the fifth bottle in a recommendation needs a countable list. A passage mentioning gin may find the right conversation while omitting the fifth entry. The next request should be able to reopen that list, identify its fifth item and cite the original bytes. For “which tickets were still blocked?”, a deterministic query can instead inspect every recorded transition and return examples and a count scoped to a particular revision.

This report tests how far ordinary retrieval, lossless storage and deterministic queries get us today. All reported runs are model-free.

## Buying useful words inside the window

We ran six treatments on the pinned cleaned LongMemEval-S release. The starting lane is the production atom ranker. An alternate lane interleaves those atoms with whole messages from three lexically matched sessions. Both return up to 24 candidate addresses. Each lane gets three packing rules. The first sends entire candidates that fit. The other two visit distinct messages first, select a short original span from each candidate, then grow contiguous spans to the left and right in rounds. One starts at the beginning. One starts at the span matching the most highly weighted question terms. Every header, source address, timestamp, role and newline counts toward 8,000 UTF-8 bytes. Every selected span was checked against its original source. The selector receives only the question, dates, roles, contents and ranks.

|---|---:|---:|---:|
| Original atoms, whole | 343 | 145 | 137 |
| Original atoms, grow from opening | 362 | 142 | 132 |
| Original atoms, grow around question terms | 362 | 145 | 135 |

| Atoms and routed messages, grow from opening | 380 | 145 | 134 |
| Atoms and routed messages, grow around question terms | **380** | **151** | **139** |

At the same 8,000-byte cap, routing and growing exact excerpts recovered all annotated messages on 37 additional questions and lost none against the original packets. Among the 170 questions whose full reference answer occurs in an annotated message, ten gained that string and four lost it. Dropping cases where the question itself names the answer leaves six gains and four losses. This explains why a gain of 7.9 percentage points on source coverage cannot support the same claim about answer quality. Some answers require combining dates or doing arithmetic. Others can be expressed correctly with different wording. The literal check ignores case and repeated whitespace and requires word boundaries. The 30 abstention questions have no positive source set for this comparison. These exploratory runs reused the development benchmark. [Aggregate and paired counts](excerpt-growth.json) · [Per-question outcomes](excerpt-cases.json.gz) · [Selector and scorer](../../docs/experiments/longmem/excerpt_growth.py)

**Four regression cases identify a better recall operation.** The compact excerpts lost a tourism-board phone number (`71a3fd6b`), the fifth bottle in a list (`3249768e`), the last Portland venue in a recommendation (`e982271f`) and a snapper dish with fruit (`778164c6`). Gains included the yoga studio (`6ade9755`) and a requested musical sequence (`eaca4986`). A first pass can locate plausible sources. A follow-up for a list position should open the whole list in order, for a phone number the complete contact entry, and for a comparison the dated assertion on each side. Each request can name a specific fact still needed. This hypothesis needs an independent answer test with the same allowance for a second ordinary search. ## The frozen policy on a second conversational benchmark

On public LoCoMo-10, the combined session and message search represented every annotated source turn for **958 of 1,533 questions (62.5%)**, compared with **890 (58.1%)** from the original ranking. There were 84 gains and 16 losses. All ten dialogues had a positive net change. The result was the same for plain BM25 and the existing fused primary ranker. On 478 cases where the question omitted a literal reference answer present in an annotated source, the packets retained that answer in 361 cases versus 330.

**Every candidate pool fit.** The median delivered packet was 4,037 bytes for the original fused ranking and 4,113 bytes after routing. The short turns left room for the entire pool, so growing excerpts added no coverage. The gain comes from which messages the combined route found. That route also indexes speaker names and session dates. This run cannot isolate which of those changes produced the gain. On LongMemEval, routing alone made the final packet worse and growing the excerpts recovered the gain. Together the two tests support a simple conditional policy. Route at both message and session level, deliver the original candidates whole when they fit, and test adaptive excerpt packing when they overflow.

The retrieval policy and its settings were frozen before scoring LoCoMo. Eligibility excluded 446 adversarial questions, four without evidence labels and three with an unresolvable source annotation. Six of the included questions needed a mechanical ID spelling repair. The 1,527 original-ID cases gave the same net gain of 68. This evaluates text across ten conversations with correlated questions. Images and captions were excluded. No reader has yet answered the questions from these packets. ## A public control for operations a program can finish exactly

ContextBench publishes lengthy synthetic log conversations with independent gold answers. We replayed all eight released 12,800-row log-triage histories. Before seeing the questions, the indexer counted events by severity and service and saved a source offset for each request ID. It used the published record grammar. Both this program and a direct per-question scan answered all **192/192** lookup and counting questions correctly. The index inspected 11.40 MB once and reopened 5,738 bytes of answers. The scans covered 203.80 MB in logical byte ranges. In our warm in-memory replay the direct scan took about 75 ms and building and querying the index took about 120 ms across all eight histories. Bytes traversed, model tokens, disk I/O and wall time are different measurements. The public fixtures establish exact execution on these schemas. They do not score extraction from ordinary dialogue or an agent choosing the right operation. [Pinned upstream tasks](https://github.com/RulinShao/ContextBench/tree/fb533c18c78a82d3f1b2047a9c1700735cf829ae/tasks/log-triage-L12800-seed42) · [Replay and inputs](../../docs/experiments/contextbench/README.md) · [Raw measurements](contextbench.json)

The previous million-event correction experiment provides a second control. Its current first page occupies 473 bytes including the snapshot-bound cursor, the exact count and two original witnesses. An unreadable event of unknown scope makes the exact count unavailable. The result is conditional on the specified grammar, snapshot and trusted index. For a natural-language request such as “did anyone ever quietly withdraw approval?”, even a perfectly functioning lexical index can miss the only decisive exception. If one exception is uniformly located among N unchecked turns, sampling k of them without replacement finds it with probability k/N. A 95% chance of finding that single exception takes a 95% sample. A trusted deterministic index can sometimes rule out whole regions. A semantic similarity score offers no equivalent guarantee. Keep the set searched, unresolved evidence and the basis for any claim of completeness available to the reader. [Million-event correction test](million-event-run.json)

## Compress bytes on disk and keep every word

Across 246,750 public LongMemEval message occurrences, independently decodable 4 KiB blocks reduced the body archive and addressing metadata from **250.37 MB to 113.26 MB** with every occurrence stored separately. The benchmark reconstructed the full ordered stream, verified the address map and served 2,000 exact 96-byte source spans. A second run reproduced every deterministic figure. A 64 KiB block saved a further 17.75 MB, but those same scattered reads expanded 131.14 MB of data versus 8.40 MB with 4 KiB blocks. These figures cover the message bodies and address table. Session metadata, Git and the full-text index have separate costs.

A promising next storage experiment is to keep frequently reopened sources in small independently verified blocks and coalesce reads of several citations that share a block. Put cold sequential histories into larger blocks. Make each logical citation identify the record, body digest and byte range so rebuilding a physical pack can preserve citations. Keep the human-edited Obsidian notes as ordinary files. Use actual packet-and-recall traces to compare mixed layouts with uniform 4 KiB, uniform 64 KiB and raw SQLite BLOBs. Publish the p95 reopen time, physical bytes fetched and decompressed bytes per byte shown to the model. The ordinary Go packet builder still reads all turn bodies. Dropping a pack reader underneath that scan alone cannot give query latency independent of corpus size. [Storage comparison, controls and runners](../../docs/experiments/source_layout/README.md)

Two published index designs supply stronger controls for that experiment. **OptFSST** uses static symbol tables for fine-grained random access to strings. Its authors report a 7.3% average improvement in compression factor over FSST across 92 string datasets. Test decoding one atom per citation with the dictionary and offsets counted in the archive size. **Move-r** is a compressed full-text index for counting and locating exact substrings in repetitive data. On a sealed segment of versioned documents or repeated tool logs it could answer literal identifier lookups and return all positions. Use record boundaries to reject cross-record matches, translate offsets back to original bytes, and compare build cost, size and lookup latency against SQLite trigram FTS and raw grep. Repetition, query mix and index reuse determine whether the extra structure pays here. [OptFSST, August 2026 revision](https://arxiv.org/abs/2607.11271) · [Move-r, SEA 2024](https://doi.org/10.4230/LIPIcs.SEA.2024.1)

## Two improvements in the ordinary Go paths

- **Recall.** Five search phrases in one recall request now share one verified collection of turn bodies. At 2,048 indexed synthetic turns, this reduced file reads from 10,240 to 2,048. The median five-query request fell from 797 to 240 ms and allocated 55 MB versus 152 MB before. Both returned the same five planted source IDs. One-query requests were similar. Missing or corrupted turn files now produce an explicit read failure. Ranking still runs per query, and SQLite full-text lane errors can still suppress hits. An empty ranking supplies no proof that the archive lacks an answer. [Implementation](../../internal/engine/recall.go) · [Benchmark fixture](../../internal/engine/recall_bench_test.go)
- **Import.** The writer determines the highest existing numeric turn ID once per transcript, in bounded batches of filenames, and allocates subsequent IDs while holding the vault writer mutex. Previously every imported message restarted the directory scan. Three alternating pairs of complete 4,096-message CLI imports took a median of **36.87 s before and 19.09 s after**. All six runs produced the same committed Git tree for the turn files and passed SQLite integrity and row-count checks. Individual trials were noisy on this shared laptop. On a write failure the importer reports how many complete turns reached disk. A retry with the unconsumed suffix continues the import. [Importer](../../internal/vault/import.go) · [Trials](import-batch.json) · [End-to-end benchmark](../../docs/experiments/import_batch.py)

## What would justify a breakthrough claim

Prior art already supports raw logs, hierarchical reopening and exact aggregate execution. GrepMem trains a reader to recover information by searching an append-only log. Folio exposes progressively recoverable context. ExecutionRAG follows unresolved subquestions and finds that recovering evidence can shift errors into premature answers. A November state-tracking study found that selecting the deciding events at query time could match a write-time filter on one domain. Quorum showed that top-ten recall of individual statutes concealed how rarely every required statute was found. Each supplies a baseline or a failure mode for this project. [GrepMem, Nov 18 preprint](https://arxiv.org/abs/2611.25123) · [Folio, Nov 12 preprint](https://arxiv.org/abs/2611.16627) · [ExecutionRAG, Oct 15 preprint](https://arxiv.org/abs/2610.21184) · [Explicit state, Nov 2 preprint](https://arxiv.org/abs/2611.02361) · [Quorum, NLLP 2026](https://aclanthology.org/2026.nllp-1.22/)

**The differentiating experiment is a reader that resumes a partially answered question after the archive changes and can show exactly what changed its answer.** Persist the query, snapshot, evidence spans already read and facts still needed. For supported structured operators, record their dependencies and inspect only new relevant records on resume. For open-ended questions, allow the reader to name missing evidence, reopen an ordered source or ask for counterevidence. Expose unresolved scope. Include a backdated reversal, a plausible same-name distractor and a correction whose wording shares no keywords with the original. A previous snapshot must reproduce its original evidence.

Freeze that behavior on development material. Compare plain search, full history where it fits, overflow-only one-time summaries, a budget-matched second search and the resumable reader on unseen conversations. Require the same reader and judge, exact quotes that support the answer, matched total input allowance including the first packet and tool results, and a fixed call limit. Report answer wins and losses, false completeness, abstention, compute and storage separately. An interrupted agent task should also be scored by whether its original verification tests pass after resumption. Evaluate archive size and history churn independently of task difficulty. A reader that stays accurate after a correction at constant input size is a stronger public result than a large on-disk corpus alone. [LiveCtx, Nov 5 journal article](https://link.springer.com/article/10.1007/s10791-026-10807-5) · [CompAct-Bench, Nov 19 preprint](https://arxiv.org/abs/2611.25673)

## Reproduction

Use the pinned LongMemEval dataset and rank-generation commands in the [public comparison guide](../../docs/experiments/longmem/README.md). From the repository root:

```sh
python3 docs/experiments/longmem/excerpt_growth.py "$data" "$work/ranks.jsonl" --cases "$work/excerpt-cases.json"
python3 docs/experiments/longmem/excerpt_growth.py "$data" "$work/ranks.jsonl" --show 71a3fd6b --arm routed_query_grow
go test ./internal/engine -run '^$' -bench '^BenchmarkRecallRequest$' -benchtime=2x -count=4
```

For the paired import comparison, build one `cx` executable from `04e171c` and one from this checkout, then pass the two paths to `python3 docs/experiments/import_batch.py BASELINE CANDIDATE`. This includes indexing and committing the imported transcript. The storage and public log replays have separate pinned instructions linked above.
